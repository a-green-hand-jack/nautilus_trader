# 设计原则

## 消息不可变性

一条消息（请求、响应、事件或命令）一旦创建，其字段就不能再被修改。
关于由此产生的所有权规则，请参见 [消息总线：消息完整性](../concepts/message_bus.md#message-integrity)。

这一不变性保护了系统所依赖的若干重要属性：

- **确定性（Determinism）**：每个消费者看到的输入都是相同的。这使得系统行为更容易推理、
  重放和测试。
- **时序完整性（Temporal integrity）**：一条消息保留了系统发出它时的真实状态。事件和
  命令因此始终是事实记录，而不是随状态漂移而变化的容器。
- **更安全的并发（Safer concurrency）**：读取方无需协调即可保护消息负载不被后续改写。
  这消除了围绕共享状态的常见竞态来源。
- **更易调试（Easier debugging）**：日志、追踪、重放工具以及死信检查仍然有用，
  因为消息始终反映其原始负载。
- **可靠的重放与仿真（Reliable replay and simulation）**：重放一段消息序列会得到与
  原始运行相同的逻辑输入，从而支持回测（backtesting）、事故重建以及回归测试。
- **清晰的所有权边界（Clear ownership boundaries）**：各组件将收到的消息视为输入。如果
  某个组件需要不同的表示形式，它会显式地派生出新的本地状态或新消息。
- **更好的可审计性（Better auditability）**：系统能够回答它当时知道什么、何时知道的，
  以及基于这些信息做了什么。
- **更强的分布式健壮性（More robust distribution）**：序列化消息本身就是作为副本跨进程
  和跨服务边界传递的。同样的所有权规则使内存中的模型与这一事实保持一致。
