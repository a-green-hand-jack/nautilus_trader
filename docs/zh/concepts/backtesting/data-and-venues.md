# 回测数据与交易场所

## 数据

用于回测的数据驱动着执行流程。由于可以使用多种类型的数据，确保你的交易场所（venue）配置与提供给回测
的数据相匹配至关重要。数据与配置不匹配可能会导致执行过程中出现意外行为。

NautilusTrader 主要为订单簿（order book）数据设计并进行了优化，这类数据完整地表示了市场中每一个价格
档位或订单，反映了交易场所的实时行为，能够提供最精细的执行粒度和最高的真实度。但如果无法获取或不需要
粒度如此精细的订单簿数据，该平台也能够按照以下由细到粗的顺序处理市场数据：

```mermaid
flowchart LR
    L3["L3 订单簿<br/>（逐单，market-by-order）"]
    L2["L2 订单簿<br/>（逐档，market-by-price）"]
    L1["L1 报价<br/>（最优挂单，top of book）"]
    T["成交明细"]
    B["K 线"]

    L3 --> L2 --> L1 --> T --> B

    style L3 fill:#2d5a3d,color:#fff
    style L2 fill:#3d6a4d,color:#fff
    style L1 fill:#4d7a5d,color:#fff
    style T fill:#5d8a6d,color:#fff
    style B fill:#6d9a7d,color:#fff
```

1. **订单簿数据/增量更新（L3 逐单，market-by-order）：**
   - 完整的市场深度，可见所有单个订单。

2. **订单簿数据/增量更新（L2 逐档，market-by-price）：**
   - 覆盖所有价格档位的市场深度可见性。

3. **报价（L1 逐档，market-by-price）：**
   - 仅最优挂单——最优买价（best bid）和最优卖价（best ask）的价格与数量。

4. **成交明细（Trade Ticks）：**
   - 实际发生的成交。

5. **K 线（Bars）：**
   - 在固定时间间隔内聚合的交易活动（例如 1 分钟、1 小时、1 天）。

### 数据选择：成本与精度的权衡

对于许多交易策略而言，K 线数据（例如 1 分钟）已足以用于回测和策略开发。这一点尤为重要，因为相比 tick
数据或订单簿数据，K 线数据通常更容易获取，且成本更低。

鉴于这一实际情况，Nautilus 的设计支持基于 K 线的回测，并提供高级特性以最大限度提升模拟精度，即便在
使用粒度较低的数据时也是如此。

:::tip
对于某些交易策略而言，先用 K 线数据开始开发以验证核心交易思路是切实可行的做法。如果该策略看起来有前景，
但对精确的执行时机更为敏感（例如需要在 OHLC 各价位之间的特定价格成交，或使用较紧的止盈/止损位），你
可以再投入使用更高粒度的数据以进行更准确的验证。
:::

## 交易场所

在为回测初始化交易场所时，你必须从以下选项中指定其内部订单 `book_type`（订单簿类型），用于执行处理：

- `L1_MBP`：一档逐档（Level 1 market-by-price，默认）。仅维护订单簿的最优层级。
- `L2_MBP`：二档逐档（Level 2 market-by-price）。维护订单簿深度，每个价格档位聚合为单个订单。
- `L3_MBO`：三档逐单（Level 3 market-by-order）。维护订单簿深度，并按照数据提供的方式跟踪每个
  单独的订单。

`book_type` 决定了撮合引擎使用哪些数据类型来更新订单簿状态并驱动执行。对于给定 `book_type` 不适用的
数据类型，会在订单簿和价格更新时被忽略，但精度校验仍然适用，且引擎时钟仍会继续推进。无论
`book_type` 为何，策略始终会通过数据引擎接收所有已订阅的数据。

| 数据类型            | L1_MBP             | L2_MBP             | L3_MBO             |
| ------------------- | ------------------ | ------------------- | ------------------- |
| `QuoteTick`          | 更新订单簿          | *忽略*               | *忽略*               |
| `TradeTick`          | 触发撮合            | 触发撮合             | 触发撮合             |
| `Bar`                | 更新订单簿          | *忽略*               | *忽略*               |
| `OrderBookDelta`     | *忽略*               | 更新订单簿           | 更新订单簿           |
| `OrderBookDeltas`    | *忽略*               | 更新订单簿           | 更新订单簿           |
| `OrderBookDepth10`   | 更新订单簿          | 更新订单簿           | 更新订单簿           |

:::note
数据的粒度必须与指定的订单 `book_type` 相匹配。Nautilus 无法从低粒度数据（例如报价、成交明细或 K
线）中生成更高粒度的数据（L2 或 L3）。
:::

:::warning
如果你将交易场所的 `book_type` 指定为 `L2_MBP` 或 `L3_MBO`，报价和 K 线将不会更新订单簿。请确保你
提供了订单簿增量（order book delta）数据，否则订单可能会看起来永远无法成交。
:::

:::warning
使用 `L1_MBP`（默认值）时，订单簿增量数据会被撮合引擎忽略。如果你订阅了订单簿增量数据，请将交易
场所的 `book_type` 设置为 `L2_MBP` 或 `L3_MBO`。这同样适用于沙盒（sandbox）执行，因为撮合引擎
使用相同的 `book_type` 配置。
:::
